What lives in Wix — and what doesn’t

The scope boundary, drawn explicitly. Everything left of the line is a Wix Studio build task Jacob can maintain; everything right is an external account the client controls.

Built in Wix Studio

  • ~14 pages — home, menu, locations index, catering, about, licensing, order, gift cards, careers, contact, privacy, terms, accessibility (+404)
  • Locations CMS — dynamic /locations/[slug] template, 14+ rows, status + venue-type fields
  • MenuItems CMS — categories, prices, dietary tags, featured flags
  • Forms ×3–4 — licensing, catering, contact, careers (+ inline success states)
  • Order-picker lightbox — store select → Toast/UberEats hand-off
  • 301 redirects — all 168 legacy URLs via Wix URL Redirect Manager
  • SEO controls — meta, OG, structured data for stores (LocalBusiness)
  • Announcement strip · sticky header · hero video · image optimization

Handled outside Wix

  • Checkout — Toast (pickup) · UberEats (delivery) — outbound only
  • Catering commerce — EZCater per-store stores
  • Email / CRM + automations — Mailchimp (VIP list, birthday offer)
  • UGC — Instagram (feed app needs client auth)
  • Analytics — GA4 + Search Console (Google accounts)
  • Gift cards — provider TBD
  • Domain / DNS — registrar transfer away from Serpcom at launch
Hard boundary: no custom ordering, cart, checkout, payments, delivery logistics, or order management — existing third-party ordering and EZCater remain external, per scope. Wix Studio is the capability ceiling: any pattern borrowed from the competitive set (Sweetgreen-grade filters, custom interactions) gets vetted against what Wix + Jacob’s maintenance capacity can sustain before it’s promised.

  • Clearlake — old URLs = future One Clearlake store pages, or dead location?

v2 drew the reconciliation — every old URL answered for. v3 finishes the argument: the same consumer spine now carries the three things the kickoff added (VIP, Instagram, real catering), every section and interaction is placed, and the build’s external dependencies are named in one registry with their asks attached. Nothing in this structure invents a price, an address, an ordering URL, or a licensing claim — placeholders and CMS fields only, per project rules.
